# 开源范围与发布检查

本仓库于2026-11-04按MIT许可证公开发布自有源码、工具与文档。运行资产与完整历史备份单独私有保管；源码发布不代表整个校园模型或森园区链路已验收通过。

公开范围是本项目自有查看器与相关工具，按仓库MIT许可证发布；使用的Three.js同为MIT，必须保留其原许可证与署名。第三方许可证中的合法作者姓名和邮箱是许可文本的一部分，不作为提交者的私有邮箱删除。

真实校园数据和模型、原始照片、课程PPT、平台原始请求/响应、历史场景证据、完整资源备份、登录材料及平台端点不在公开范围内。旧的私有Release和备份不能因为准备公开源码而被一起公开；prerelease标记也不是隐私保护。真实素材的授权与来源不由本仓库的MIT许可代为授予。

## 本地检查

在候选根目录执行：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_public_audit.py'
PYTHONDONTWRITEBYTECODE=1 python3 scripts/audit_public.py
PYTHONDONTWRITEBYTECODE=1 python3 scripts/audit_public.py --history
```

审计默认扫描整个候选树，不跟随软链。除了Git元数据，只有被`.gitignore`明确忽略且未受跟踪的测试缓存可以跳过；其他忽略规则不能把私有文件藏进公开候选。受跟踪的文件即使后来被忽略，仍会检查。

检查会拦截高置信令牌、完整私钥、用户绝对home路径、真实内网IPv4、场景标识、长平台标识、原始平台材料、模型和课程文件，以及未获豁免的二进制、软链。loopback和TEST-NET示例地址允许保留。输出只包含相对路径、行号和类别，不回显匹配值。

`--history`检查全部**本地可用refs**关联的提交、历史blob、已删除文件和提交者邮箱；公开候选提交必须使用GitHub noreply邮箱。浅克隆、未初始化Git或尚无提交的仓库会失败。扫描不改写历史、不删除文件，也不连接远端，因此运行前必须确认本地refs已覆盖远端全部分支和标签。仅检查当前工作树不能证明旧历史安全。

测试使用临时目录，在运行时通过字符串拼接构造模拟泄漏；测试源码自身没有保存可用凭据。扫描器不是所有秘密或许可问题的通用证明，仍需人工复核新增数据、文件来源和图片元数据。

## 公开前的远端门禁

1. 确认候选是干净的新历史，或已对所有拟公开分支、标签及历史文件完成清理；不要把未经审计的旧refs推入候选。
2. 对比远端全部refs与本地检查范围。若有旧PR refs或其他可达历史，须纳入审查，不能只扫描默认分支。
3. 检查全部Releases，包括已发布、草稿和prerelease的附件；公开候选必须没有私有完整备份、课程材料、真实模型、原始平台证据或含隐私的manifest。已有私有附件的原仓库继续保持private，不能直接改可见性。
4. 核对自有源码许可证、Three.js原MIT许可证、署名、公开范围和README运行要求。源码检查或单元测试通过不能替代真实资产、平台动画及模型贴地验收。
5. 只有上述门禁均通过，才可执行实际发布。此文件不执行或授权远端可见性变更。
